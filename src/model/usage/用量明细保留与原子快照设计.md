# 用量明细保留与原子快照设计

## 目标与边界

用量明细只保留最近 30 天，并沿用每 Key／账号最多 10,000 条的内存保护。启动时和每小时清理，不依赖新请求。清理只删除明细，累计请求数、token、费用及 credits 继续保留；费用额度检查必须包含已清理部分。日报与区间报表继续只统计留存明细。

## 持久化与兼容

当前明细直接覆盖 JSON 文件，进程被 OOM 杀掉可能截断文件；明细与累计基数分别落盘也可能产生不一致。将二者改成同一个带版本的 JSON 快照，同目录临时文件写入、fsync 后原子替换。加载仍接受原数组及旧累计基数文件，只在首次保存时迁移；新快照是唯一权威。损坏文件显式报错，不静默归零。回滚旧程序必须同时恢复升级前数据备份。

## 验证

覆盖 30 天边界、无新请求的定时清理、累计与额度检查不倒退、重启幂等、旧格式迁移、写入失败保留旧文件及未知版本拒绝。仅运行专项单元测试、格式和 lint；部署检查不调用模型，不运行 E2E。
